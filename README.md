# Screen Recorder & Transcriber

Десктопное приложение для Ubuntu: запись экрана, конвертация в аудио,
транскрибация, суммаризация, библиотека поиска и интеграция с Bitrix24.
**Все файлы сохраняются локально.**

Версия: **1.1.0**

## Возможности

### Запись
- Запись экрана через `ffmpeg` (X11: `x11grab` + `libx264`, Wayland: `kmsgrab` + `h264_vaapi`).
- Пауза/возобновление записи.
- Наложение водяного знака (только под X11).
- Плавающая панель управления с кнопками Старт/Пауза/Стоп.
- Системный трей.
- Глобальные горячие клавиши (`Ctrl+Shift+R` — старт/пауза, `Ctrl+Shift+S` — стоп).

### Обработка
- Автоматическая конвертация видео в аудио (mp3/aac/wav/opus).
- Транскрибация через внешний сервис (Whisper).
- Суммаризация двумя путями: **сервер транскрибации** или **LiteLLM**
  (OpenAI-совместимый API — GPT, Claude, локальные модели и т.п.).
- Глоссарий терминов — помогает ИИ распознавать специфические
  названия и аббревиатуры.
- Формирование файла промпта для **DeepSeek** (скрам-митинги) со
  стенограммой, предыдущим протоколом и вложениями.
- Сохранение форматирования вложений при экспорте в `.docx`
  (заголовки, списки, жирный/курсив, таблицы).

### Метаданные и организация
- Диалог метаданных с вкладками: **Основное**, **Промпт**,
  **Скрам и DeepSeek**, **Вложения**.
- **Проект, название, комментарий, теги** — на вкладке «Основное».
- **Шаблоны названий** с плейсхолдерами (`{name}`, `{date}` и т.п.).
- **Библиотека промптов** — готовые инструкции на выбор.
- **Контекст записи в промпте** — можно включать/отключать
  передачу названия, проекта, комментария и тегов в промпт.
- **Summary** для каждой записи (Markdown, с редактором и просмотрщиком).
- **Менеджер сессий** — таблица всех записей с фильтрами и статусами.

### Теги
- Справочник тегов (**Настройки → Теги**) с цветовой подсветкой.
- Несколько тегов на одну запись.
- Фильтр по тегу в **Библиотеке** (можно искать только среди
  записей с выбранным тегом или только среди записей без тегов).
- Теги сохраняются в `session.json` каждой записи.

### Импорт и поиск
- **Импорт** готовых материалов: видео/аудио, стенограмма, протокол.
  Можно сразу проставить теги.
- **Библиотека** — полнотекстовый поиск по стенограммам, протоколам,
  summary и вложениям. Нечёткий (fuzzy) поиск для расшифровок с
  опечатками.
- Фильтры: **проект**, **тег**, **период дат**.
- **Формирование промпта** из результатов поиска — с настройкой
  размера контекста, дедупликацией, экспортом в `.docx` / `.md`.

### Интеграция с Bitrix24
- Отправка **протокола и/или summary** в чаты Bitrix24.
- **Массовая отправка** нескольким получателям сразу: проекты,
  сотрудники и ручной ID чата.
- Два режима: **текстом** в чат или **файлом с комментарием**.
  Для текста есть порог «текст → файл».
- Протокол автоматически конвертируется в `.docx` перед отправкой.
- Файлы загружаются на **Диск Bitrix24** в **папку самого чата** —
  вложение корректно видно всем участникам.
- Автоматическое преобразование Markdown в BB-код Bitrix24
  (`[B]`, `[I]`, `[URL]`, `[QUOTE]`, `[LIST]`).
- Редактируемые заголовки сообщений прямо в диалоге отправки.
- Отправка нескольких файлов **одним сообщением**.

### ВМ Yandex
- Отдельное окно (**трей → ВМ Yandex**) для просмотра и
  редактирования конфигураций виртуальных машин Yandex Cloud.
- Каждая ВМ — подпапка в корневой папке. Внутри:
  - `schedule.cron` — расписание работы ВМ;
  - `exceptions.txt` — исключения (переопределения).
- Редактор с индикацией несохранённых изменений и атомарной
  записью на диск.

### Хранение и очередь
- Локальное хранение результатов — без отправки на NAS.
- Очередь задач с авто-ретраем неудачных.
- Восстановление очереди после перезапуска.
- Подробное логирование с ротацией.
- Система подсказок (ⓘ) для всех полей интерфейса.
- **Экспорт/импорт настроек** в JSON (с резервной копией конфига).
- **Версия приложения** в правом нижнем углу окна настроек
  (клик — копирование в буфер обмена).

## Установка

### Из .deb-пакета (рекомендуется)

```bash
# Сборка пакета
./build_deb.sh

# Установка
sudo dpkg -i build/screen-recorder_<версия>_all.deb
sudo apt-get install -f     # доустановить зависимости, если нужно
```

Пакет сам создаст виртуальное окружение в `/opt/screen-recorder/venv`
и установит Python-зависимости (занимает 1–3 минуты при первой установке).

Запуск: `screen-recorder` или через меню приложений.

### Из исходников

```bash
sudo apt update
sudo apt install -y ffmpeg python3 python3-pip python3-venv python3-full \
                    x11-utils vainfo \
                    intel-media-va-driver-non-free i965-va-driver-shaders \
                    gnome-shell-extension-appindicator
cd screen-recorder-app
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### Зависимости

Обязательные:

- `PySide6` — GUI
- `aiohttp` — асинхронные HTTP-клиенты (LiteLLM, транскрибация, Bitrix24)
- `keyring` — хранение мастер-ключа шифрования
- `cryptography` — шифрование чувствительных данных (Fernet)
- `python-docx` — чтение/запись `.docx` (протоколы, стенограммы, вложения)
- `pypdf` — чтение `.pdf` (вложения и протоколы)
- `pynput` — глобальные горячие клавиши

Системные (для записи экрана):

- `ffmpeg` — запись и конвертация
- `x11-utils` — `xrandr` для списка мониторов
- `vainfo`, `intel-media-va-driver-non-free`, `i965-va-driver-shaders` —
  аппаратное кодирование под Wayland
- `gnome-shell-extension-appindicator` — корректная иконка в трее под GNOME

### Для Wayland (kmsgrab)

```bash
sudo usermod -aG video $USER
sudo usermod -aG render $USER
sudo setcap cap_sys_admin+ep $(which ffmpeg)
# logout/login
```

## Куда сохраняются файлы

По умолчанию:

```
/tmp/screen-recorder/sessions/<YYYY-MM-DD_HH-MM-SS>/
├── video.mp4                    ← запись
├── video.ffmpeg.log             ← stderr ffmpeg
├── video.mp3                    ← аудиодорожка
├── video.txt                    ← стенограмма (если включён сервер)
├── video_summary.md             ← резюме (если включена суммаризация)
├── deepseek_prompt.docx|md|txt  ← промпт для DeepSeek (скрам)
├── manual_protocol.docx|pdf|... ← прикреплённый протокол
├── session.json                 ← метаданные записи (включая теги)
└── attachments/                 ← вложения
    └── ...
```

**Важно:** `/tmp` очищается при перезагрузке. Чтобы сохранять файлы надолго:

1. Откройте настройки (левый клик по иконке в трее).
2. Вкладка **«Хранилище»**.
3. Укажите **постоянную** папку, например `/home/user/Videos/screen-recorder`.
4. Сохранить.

## Настройка

Окно настроек открывается **левым кликом** по иконке трея → «Настройки».

### Вкладки настроек

- **Проекты и чаты Bitrix24** — реестр проектов с привязкой к чатам,
  а также проект и чат по умолчанию.
- **Теги** — справочник меток с цветовой подсветкой.
- **Сотрудники** — ФИО и ID личного чата для массовой рассылки.
- **Bitrix24** — вебхук, таймауты, режим отправки файлов.
- **Промпты и имена** — библиотека промптов и шаблоны названий записи.
- **Транскрибация** — URL сервера и access key.
- **Суммаризация** — провайдер (сервер / LiteLLM) и его параметры.
- **Глоссарий** — термины и аббревиатуры для ИИ.
- **Запись** — монитор, микрофон, водяной знак, горячие клавиши.
- **Очередь** — авто-ретрай, интервал, максимум попыток.
- **Скрам** — шаблон промпта для DeepSeek и формат экспорта.
- **ВМ Yandex** — корневая папка с конфигурациями ВМ.
- **Форматы и сжатие** — аудио, видео битрейты, сжатие.
- **Хранилище** — путь к папке сессий и срок хранения.
- **Логи** — путь и уровень логирования.

Каждая вкладка содержит подсказки (ⓘ) для полей и кнопку «Помощь»
с развёрнутой справкой по этой вкладке.

В правом нижнем углу окна — **версия приложения**. Клик копирует
номер в буфер обмена.

### Кнопки внизу окна

- **Помощь** — справка по текущей вкладке.
- **Экспорт настроек…** — сохранить весь конфиг в JSON.
- **Импорт настроек…** — загрузить конфиг из JSON (с автоматической
  резервной копией текущего).
- **Сбросить** — сбросить форму к значениям по умолчанию
  (без сохранения).
- **Сохранить** — записать настройки на диск.
- **Закрыть** — закрыть окно без сохранения.

### Файл конфигурации

```
~/.config/screen-recorder/config.json
```

### Шифрование секретов

Мастер-ключ хранится в системном keyring (GNOME Keyring / KWallet).
Если keyring недоступен — используется файл `~/.config/screen-recorder/.fernet_key`
с правами `0600`. Ключ можно экспортировать/импортировать (методы
`get_raw_key` / `import_key` в `ConfigManager`).

### Временные файлы

```
/tmp/screen-recorder/
├── app.log              # логи приложения
└── queue.json           # очередь задач
```

## Что происходит после остановки записи

1. Файл `video.mp4` **остаётся** в `<temp_path>/sessions/<timestamp>/`.
2. Создаётся `session.json` с метаданными (проект, название,
   комментарий, теги, промпт, вложения и т.п.).
3. Вложения копируются в `<session>/attachments/`.
4. Выполняется **конвертация в аудио** (`video.mp3`).
5. Если в настройках задан **URL сервера транскрибации** — выполняется
   транскрибация, результат сохраняется в `video.txt`.
6. Если провайдер суммаризации — **LiteLLM**, после транскрибации
   выполняется запрос к нему и сохраняется `video_summary.md`.
7. Если запись помечена как **скрам-митинг** — собирается файл
   `deepseek_prompt.docx` (или `.md`/`.txt`) с готовым промптом
   для DeepSeek.
8. **Загрузка на NAS не выполняется** — приложение работает в
   локальном режиме.

## Интеграция с Bitrix24

### Что нужно настроить

1. В Bitrix24 создайте **входящий вебхук** (Приложения → Разработчикам
   → Вебхуки) и разрешите методы: `im`, `disk`, `im.disk`.
2. В настройках приложения → **Bitrix24**:
   - включите интеграцию;
   - вставьте URL вебхука;
   - настройте поведение отправки (заголовки, системные сообщения,
     предпросмотр ссылок);
   - задайте порог «текст → файл» (тексты длиннее — уходят вложением);
   - при необходимости укажите ID папки на Диске (по умолчанию
     используется папка самого чата).
3. В настройках → **Проекты и чаты Bitrix24** для каждого проекта
   укажите ID чата (`chat2101` или `2101`).
4. В настройках → **Сотрудники** добавьте ФИО и ID личного чата
   для сотрудников, которым нужно отправлять сообщения напрямую.
5. При необходимости задайте **проект и чат по умолчанию** —
   они подставятся автоматически при создании новых записей
   и при отправке протоколов/summary.

### Как отправить

1. Откройте **Записи**.
2. Выберите нужную запись.
3. Меню **Bitrix24 → Отправить в чат…** (или сразу «протокол» /
   «summary» / «Отправить всё»).
4. В диалоге:
   - на вкладке **«Получатели»** отметьте один или несколько чатов
     (проекты, сотрудники), при необходимости добавьте ID вручную;
   - на вкладке **«Содержимое»** выберите режим отправки:
     **Автоматически** / **Текстом** / **Файлом**;
     при необходимости отредактируйте заголовки;
   - на вкладке **«Параметры»** проверьте вебхук и опции
     (проверка подключения — кнопка «Проверить подключение»);
   - нажмите одну из кнопок отправки.
5. Перед отправкой появится диалог подтверждения со списком
   получателей и тем, что и в каком виде уйдёт.

**Файлы загружаются в папку самого чата** — это гарантирует, что
все участники увидят вложение корректно.

### Массовая отправка

Можно отправить сообщение сразу нескольким получателям:

- отметить галочками несколько проектов и/или сотрудников;
- добавить ID чата вручную в поле «Доп. ID чата»;
- использовать кнопки **«Выбрать все»** / **«Снять все»** /
  **«Показать выбранные»**;
- в конце — диалог подтверждения со списком получателей
  и превью того, что уйдёт.

## Импорт материалов

Если у вас уже есть видео, стенограмма и протокол, подготовленные вне
программы:

1. Меню трея → **Импорт** (или в окне «Записи» `Ctrl+I`).
2. Выберите файлы:
   - **Видео / аудио** — `.mp4`, `.mkv`, `.mp3`, `.wav` и др.
   - **Стенограмма** — `.txt`, `.md`, `.docx`, `.json`, `.srt`, `.vtt`.
   - **Протокол** — `.docx`, `.txt`, `.md`, `.pdf`.
3. Укажите дату, название, проект, комментарий.
4. При желании проставьте **теги** — из справочника или добавив
   новый прямо в диалоге.
5. При желании — поставьте галочку «Поставить в очередь обработки».
6. **Импортировать**.

Файлы будут скопированы в новую папку сессии под стандартными именами
(`video.<ext>`, `video.txt`, `manual_protocol.<ext>`) и появятся в
разделе «Записи» и в «Библиотеке».

## Библиотека (поиск)

Полнотекстовый поиск по всем сохранённым записям. Без базы данных —
сканирование файлов на лету.

- **Где искать**: стенограммы, протоколы, summary, вложения.
- **Fuzzy-поиск** для стенограмм — находит слова с опечатками
  (регулируется порог схожести, по умолчанию 82%).
- **Фильтры**: по проекту, **по тегу** (в том числе «— без тега —»),
  по периоду дат.
- **Результаты**: показывают, где именно найдено совпадение,
  с фрагментом контекста. Можно открыть папку записи или найденный
  файл, сохранить копию.
- **Формирование промпта** из результатов: настраивается размер
  контекста до/после совпадения, максимум фрагментов, дедупликация,
  произвольная инструкция для ИИ. Промпт можно просмотреть,
  скопировать в буфер и экспортировать в `.docx` / `.md`.

## Устранение неполадок

### 1. `externally-managed-environment` при `pip install`

Используйте venv:

```bash
sudo apt install -y python3-venv python3-full
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. `ModuleNotFoundError: No module named 'src.main'`

Запускать из корня проекта:

```bash
cd screen-recorder-app
python -m src.main
```

### 3. Пустые строки в `QComboBox`

В `resources/styles.qss` должно быть правило:

```css
QComboBox QAbstractItemView {
    background-color: palette(base);
    color: palette(text);
    border: 1px solid palette(mid);
    selection-background-color: palette(highlight);
    selection-color: palette(highlightedText);
    outline: none;
}
```

### 4. Меню в трее обрезано (GNOME)

```bash
sudo apt install -y gnome-shell-extension-appindicator
gnome-extensions enable ubuntu-appindicators@ubuntu.com
# logout/login
```

Резерв: **левый клик** по иконке открывает настройки.

### 5. Чёрный экран в записи под Wayland

Проверьте `XDG_SESSION_TYPE`. Под Wayland используется `kmsgrab` + `h264_vaapi`.
Нужны:

- `vainfo` — проверьте, что VAAPI работает;
- `/dev/dri/cardN` — доступен пользователю (группы `video`, `render`);
- `sudo setcap cap_sys_admin+ep $(which ffmpeg)`.

### 6. `Failed to open DRM device`

```bash
ls -la /dev/dri/
# должно быть cardN и renderD128

sudo usermod -aG video $USER
sudo usermod -aG render $USER
sudo setcap cap_sys_admin+ep $(which ffmpeg)
# logout/login
```

### 7. VAAPI не работает

```bash
sudo apt install -y intel-media-va-driver-non-free i965-va-driver-shaders vainfo
vainfo
# если H264 есть — работает
```

Если не работает — используйте **CPU-кодек**. В `src/recorder.py` замените
в Wayland-ветке:

```python
vf = f"{crop_expr},hwdownload,format=bgr0,format=yuv420p"
cmd += ["-vf", vf, "-c:v", "libx264", "-preset", "ultrafast",
        "-pix_fmt", "yuv420p", "-b:v", f"{video_bitrate}k"]
```

### 8. `ffmpeg` падает, а приложение «не видит»

Лог ffmpeg пишется рядом с видео:

```bash
cat /tmp/screen-recorder/sessions/<timestamp>/video.ffmpeg.log
```

Смотрите последние строки — там причина.

### 9. Overlay-панель показывает 100% и старые логи

Метод `OverlayPanel.reset()` вызывается при старте и остановке записи
(уже реализовано).

### 10. Ошибки при транскрибации

- Проверьте URL сервера во вкладке **«Транскрибация»**.
- Если URL пустой — шаг пропускается, ошибки не будет.
- Логи: `tail -f /tmp/screen-recorder/app.log | grep transcribe`.

### 11. Ошибки при суммаризации через LiteLLM

- Проверьте URL и API key во вкладке **«Суммаризация»**.
- Кнопка **«Проверить подключение»** делает ping.
- Логи: `tail -f /tmp/screen-recorder/app.log | grep -i litellm`.

### 12. Ошибки при отправке в Bitrix24

**`USER_NOT_FOUND` при `im.message.add`**
- Чат не существует или вебхук не имеет к нему доступа.
- Проверьте ID чата в настройках → «Проекты и чаты Bitrix24».

**`CHAT_ID_EMPTY` при `im.disk.folder.get`**
- Не задан ID чата, или формат неправильный.
- Используйте `chat2101` или `2101`.

**`DISK_OBJ_22000` («файл с таким именем уже есть»)**
- Уже обработано: имя файла получает временной отпечаток,
  передаётся `generateUniqueName=1`.

**`NO_ACCESS` / 403 от `disk.*`**
- У вебхука нет прав `disk` и/или `im.disk`.
- Откройте вебхук в Bitrix24, добавьте нужные методы, сохраните.

**Файл загружается, но не привязывается к сообщению**
- Проверьте, что вебхук имеет доступ к `im.disk.file.commit`.
- Логи: `tail -f /tmp/screen-recorder/app.log | grep -i "file.commit"`.

**Сообщение ушло не всем получателям**
- Итоговый отчёт после массовой рассылки показывает: сколько
  получателей, кто получил, кто — с ошибкой.
- Проверьте лог: `grep -i "Bitrix24:" /tmp/screen-recorder/app.log`.

### 13. Предупреждения Wayland про `transientParent`

```
qt.qpa.wayland: Failed to create popup. Ensure popup ... has a transientParent set.
```

Это безобидное предупреждение. Тултипы показываются корректно, но
в логе будет строка. Не критично.

### 14. «Библиотека» долго ищет на большом архиве

- Сузьте область поиска: выберите проект, тег, задайте период дат.
- Отключите поиск во вложениях, если они не нужны.
- Ограничьте глубину поиска по датам.

### 15. Кнопка «Сохранить» в настройках не срабатывает

Проверьте права на `~/.config/screen-recorder/`:

```bash
ls -la ~/.config/screen-recorder/
# владелец должен быть вами, права 700 для папки, 600 для config.json
```

### 16. Не показывается окно настроек под Wayland

Проверьте, что установлен `gnome-shell-extension-appindicator`.
Под некоторыми Wayland-композиторами (Sway, Hyprland) клик по иконке
трея может не срабатывать — используйте горячие клавиши.

## Сборка .deb

```bash
./build_deb.sh
```

Скрипт читает версию из `src/__init__.py`, собирает дерево в `build/`
и вызывает `dpkg-deb`. Результат — в `build/screen-recorder_<версия>_all.deb`.
