# Screen Recorder & Transcriber

Приложение для Ubuntu: обработка видео и документов, транскрибация, суммаризация, формирование протоколов, управление поручениями и синхронизация с сервером. **Все исходные файлы сохраняются локально**, синхронизация с сервером — опциональна.

Версия: **1.13.4**

> ⚠️ **Важно:** начиная с версии 1.13.x приложение работает в режиме **пост-обработчика**. Механизм записи экрана удалён — приложение принимает готовые видеофайлы (загрузка с диска, импорт материалов) и создаёт записи-документы из файлов.

## Возможности

### Приём материалов

- **Загрузить видео** — выбрать видео/аудиофайл с диска и поставить в очередь обработки.
- **Импорт материалов** — импорт видео/аудио + стенограммы + протокола одновременно.
- **Создать запись (документ)** — запись без видео, только из прикреплённых файлов (Word, PDF, TXT, MD, CSV, JSON, XLSX, PPTX и т.п.).
- Поддержка форматов: `.mp4`, `.mkv`, `.mov`, `.avi`, `.webm`, `.flv`, `.wmv`, `.mp3`, `.wav`, `.m4a`, `.aac`, `.opus`, `.ogg`, `.srt`, `.vtt`, `.json` и др.

### Обработка

- Автоматическая конвертация видео в аудио (mp3/aac/wav/opus) через ffmpeg.
- Транскрибация через внешний сервис (Whisper и совместимые). **Поддерживается несколько сервисов одновременно** — с выбором активного.
- Суммаризация двумя путями: **сервер транскрибации** или **LiteLLM** (OpenAI-совместимый API — GPT, Claude, локальные модели).
- Глоссарий терминов и аббревиатур — помогает ИИ распознавать специфические названия.
- Формирование файла промпта для **DeepSeek** (скрам-митинги) со стенограммой, предыдущим протоколом, вложениями и TFS-выборкой.
- Сохранение форматирования вложений при экспорте в `.docx` (заголовки, списки, жирный/курсив, таблицы).
- Извлечение текста из документов (записи без видео) — Word, PDF, TXT, MD, CSV, JSON, XLSX, PPTX.
- **Автосжатие медиа** перед публикацией, если файл превышает лимит сервера.

### Метаданные и организация

- Диалог метаданных с вкладками: **Основное**, **Документ**, **Промпт**, **Скрам и DeepSeek**, **TFS**, **Зависимости**, **Вложения**.
- **Проект**, **Категория**, **Название**, **Комментарий**, **Теги** — на вкладке «Основное».
- **Шаблоны названий** с плейсхолдерами (`{name}`, `{abbr}`, `{date}`, `{time}`, `{datetime}`).
- **Библиотека промптов** — готовые инструкции на выбор.
- **Контекст записи в промпте** — можно включать/отключать передачу названия, проекта, комментария и тегов в промпт.
- **Summary** для каждой записи (Markdown, с редактором и просмотрщиком).
- **Менеджер сессий** — таблица всех записей с фильтрами по проекту, категории, тегу, периоду.
- **Флаг «готово к синхронизации»** — защищает запись от случайной перезаписи и удаления.

### Теги и категории

- **Справочник тегов** (Настройки → Теги) с цветовой подсветкой.
- Несколько тегов на одну запись.
- Кликабельные «чипы» тегов над таблицей записей со счётчиками и фильтрацией.
- Фильтр по тегу в **Библиотеке** (включая «— без тега —»).
- **Справочник категорий** (Настройки → Проекты и чаты Bitrix24 → Категории) — тип записи (Совещание, Созвон, Встреча с клиентом и т.п.).
- Фильтр по категории в окнах «Записи» и «Библиотека».

### Импорт и поиск

- **Импорт** готовых материалов: видео/аудио, стенограмма, протокол. Можно сразу проставить теги.
- **Библиотека** — полнотекстовый поиск по стенограммам, протоколам, summary и вложениям. **Нечёткий (fuzzy) поиск** для расшифровок с опечатками.
- Фильтры: **проект**, **категория**, **тег**, **период дат**.
- **Формирование промпта** из результатов поиска — с настройкой размера контекста, дедупликацией, экспортом в `.docx` / `.md`.
- Кнопка **«Стоп»** — прерывание поиска.
- **Сводка за день (daily digest)** — единый промпт из протоколов за период.

### Поручения (action items)

- **Редактор поручений** для каждой записи (отдельное окно и встроенный в «Скрам»).
- Сводное окно **«Поручения»** по всем записям с фильтрами.
- **Сквозная нумерация** поручений (`№42 — текст`).
- 5 статусов: `created`, `in_progress`, `waiting`, `done`, `cancelled`.
- **Извлечение поручений через LLM** из стенограммы и протокола.
- **Отправка поручений сотрудникам** в Bitrix24 с fuzzy-сопоставлением ФИО.
- Импорт/экспорт JSON, вставка из буфера с поддержкой русских синонимов полей.

### Интеграция с TFS / Azure DevOps Server

- Отдельное окно **«Задачи TFS»** (`трей → Задачи TFS`).
- **WIQL-запросы** (плоские `FROM WorkItems` и `FROM WorkItemLinks`).
- **Шаблонные переменные** WIQL (`{{Проект}}`, `{{ДатаОт}}`) с диалогом ввода.
- **Сохранённые WIQL-шаблоны** с дефолтными значениями переменных.
- **Дерево связей** (link-запросы) с сохранением иерархии.
- **TFS-выборка как артефакт записи** — сохранение в `attachments/tfs_work_items.csv` (или `.md`).
- **Автоматическая передача TFS-выборки в промпт DeepSeek** (для скрам-записей).

### Интеграция с Bitrix24

- Отправка **протокола и/или summary** в чаты Bitrix24.
- **Массовая отправка** нескольким получателям сразу: проекты, сотрудники, ручной ID чата.
- **Рассылка поручений сотрудникам** — каждому отдельным сообщением, только его поручения.
- Два режима: **текстом** в чат или **файлом с комментарием**. Порог «текст → файл».
- Протокол автоматически конвертируется в `.docx` перед отправкой.
- Файлы загружаются на **Диск Bitrix24** в **папку самого чата**.
- Автоматическое преобразование Markdown в BB-код Bitrix24 (`[B]`, `[I]`, `[URL]`, `[QUOTE]`, `[CODE]`, `[SPOILER]`).
- **Списки** конвертируются в юникод-буллеты `•` (Bitrix24 не поддерживает `[LIST]`).
- **Транслитерация кириллицы** в именах файлов.
- **Публичные ссылки на записи** на сервере синхронизации с выбором блоков.
- Редактируемые заголовки сообщений прямо в диалоге отправки.
- Отправка нескольких файлов **одним сообщением**.

### Синхронизация с сервером

Работа с собственным сервером синхронизации (`screc-server`):

- **Публикация записей** на сервер (текстовые артефакты + метаданные).
- **Опциональная передача медиа** (video/audio) как артефактов.
- **Автосжатие видео** при превышении лимита артефакта.
- **Условная загрузка** через SHA-256 (экономия трафика).
- **Дельта-синхронизация** через `/sync/changes`.
- **Полная синхронизация** через `/sync/snapshot`.
- **Скачивание записей** с сервера (по одной или выборочно).
- **Синхронизация справочников** проектов и тегов.
- **Автопубликация** после обработки (опционально — только для записей с флагом `sync_ready`).
- **Фоновый pull** с настраиваемым интервалом.
- **Публичные ссылки на записи** (`/view/{project}/{year}/{month}/{folder}`).
- Отдельное окно **«Синхронизация»** с 5 вкладками: На сервер / С сервера / Дельта / Справочники / Журнал.

### Связи между записями

- Отдельная вкладка **«Зависимости»** в диалоге метаданных.
- **3 вида связи:** связан, родитель, дочерний.
- Обратные связи вычисляются динамически.
- Фильтр по связям в окне «Записи» (кнопка «Связи»).
- Связи передаются на сервер с сохранением `record_id` — не теряются при переименовании папок.

### Скрам-режим

- Отдельное окно **«Скрам»** — рабочее место скрам-митинга.
- Флаг `is_scrum` в метаданных.
- **Левая часть:** поручения + задачи TFS.
- **Правая часть:** вкладки «Протокол» и «Записи за день».
- **Сортировка по исполнителю** (настраивается).
- **Сворачиваемые панели** управления для экономии места.
- Интеграция с TFS-панелью и редактором поручений.

### Встроенные просмотрщики

- **Медиаплеер** — встроенный (Qt Multimedia), с fallback на системный.
- **Просмотрщик текста** (`.txt`) с поиском и подсветкой совпадений.
- **Просмотрщик протоколов** (`.docx` / `.md` / `.txt` / `.pdf`) с сохранением форматирования.
- **Редактор Markdown** с предпросмотром и экспортом в DOCX.

### Хранение и очередь

- Локальное хранение результатов.
- Очередь задач с авто-ретраем неудачных (настраиваемый интервал и лимит попыток).
- Восстановление очереди после перезапуска.
- Подробное логирование с ротацией.
- Система подсказок (ⓘ) для всех полей интерфейса.
- **Экспорт/импорт настроек** в JSON (с резервной копией конфига).
- **Экспорт/импорт мастер-ключа** шифрования.
- **Версия приложения** в правом нижнем углу окна настроек (клик — копирование в буфер).
- **Защита от segfault** (faulthandler + корректный порядок завершения).

## Установка

### Из .deb-пакета

```bash
# Сборка пакета
./build_deb.sh

# Установка
sudo dpkg -i build/screen-recorder_<версия>_all.deb
sudo apt-get install -f     # доустановить зависимости, если нужно
```

Пакет создаёт виртуальное окружение в `/opt/screen-recorder/venv` и устанавливает Python-зависимости (занимает 1–3 минуты при первой установке).

Запуск: `screen-recorder` или через меню приложений.

### Из исходников

```bash
sudo apt update
sudo apt install -y ffmpeg python3 python3-pip python3-venv python3-full \
                    gnome-shell-extension-appindicator
cd screen-recorder-app
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### Зависимости

Python:

- `PySide6` — GUI
- `aiohttp` — асинхронные HTTP-клиенты (LiteLLM, транскрибация, Bitrix24, TFS, sync)
- `keyring` — хранение мастер-ключа шифрования
- `cryptography` — шифрование чувствительных данных (Fernet)
- `python-docx` — чтение/запись `.docx` (протоколы, стенограммы, вложения)
- `pypdf` — чтение `.pdf` (вложения и протоколы)

Системные:

- `ffmpeg` — конвертация и сжатие медиа
- `gnome-shell-extension-appindicator` — корректная иконка в трее под GNOME

## Запуск

```bash
source .venv/bin/activate
python -m src.main
# или с DEBUG-логом
SCREEN_RECORDER_LOG_LEVEL=DEBUG python -m src.main
```

## Куда сохраняются файлы

По умолчанию:

```
/tmp/screen-recorder/sessions/<YYYY-MM-DD_HH-MM-SS>/
├── video.mp4                    ← исходное видео (если есть)
├── video.mp3                    ← аудиодорожка
├── video.txt                    ← стенограмма (или текст документов)
├── video_summary.md             ← резюме (если включена суммаризация)
├── deepseek_prompt.docx|md|txt  ← промпт для DeepSeek (скрам)
├── action_items.json            ← поручения (если извлекались)
├── action_items_prompt.docx|md  ← промпт для извлечения поручений
├── manual_protocol.docx|pdf|... ← прикреплённый протокол
├── protocol.docx|md|txt         ← сгенерированный протокол
├── session.json                 ← метаданные записи
├── .sync_published.json         ← маркер публикации на сервере
└── attachments/                 ← вложения
    ├── tfs_work_items.csv       ← TFS-выборка (если была)
    └── ...
```

**Важно:** `/tmp` очищается при перезагрузке. Чтобы сохранять файлы надолго:

1. Откройте настройки (левый клик по иконке в трее).
2. Вкладка **«Хранилище»**.
3. Укажите **постоянную** папку, например `/home/user/Videos/screen-recorder`.
4. Сохранить.

## Меню трея

Правый клик по иконке трея открывает контекстное меню:

- **Загрузить видео** — выбрать файл и поставить в очередь обработки.
- **Создать запись (документ)…** — создать запись без видео, только из файлов.
- **Импорт** — импортировать готовое видео, стенограмму и/или протокол.
- **Записи** — окно со списком всех сессий.
- **Библиотека** — полнотекстовый поиск по архиву.
- **Поручения** — сводное окно поручений по всем записям.
- **Задачи TFS** — просмотр списка задач из TFS.
- **Очередь задач** — просмотр и управление очередью.
- **Синхронизация с сервером** — окно управления синхронизацией.
- **Настройки** — окно настроек.
- **Выход**.

Левый клик — открывает окно настроек (поведение по умолчанию).

## Настройка

Окно настроек открывается левым кликом по иконке трея → «Настройки».

### Вкладки настроек

- **Проекты и чаты Bitrix24** — реестр проектов с привязкой к чатам, категории записей, проект/чат по умолчанию.
- **Теги** — справочник меток с цветовой подсветкой.
- **Сотрудники** — ФИО и ID личного чата для массовой рассылки.
- **Bitrix24** — вебхук, таймауты, режим отправки файлов.
- **Синхронизация** — подключение к `screc-server`, автопубликация, автоподтягивание.
- **TFS** — подключение к TFS / Azure DevOps Server, WIQL-шаблоны.
- **Сжатие медиа** — параметры автосжатия перед публикацией.
- **Промпты и имена** — библиотека промптов и шаблоны названий записи.
- **Транскрибация** — список сервисов транскрибации, активный сервис.
- **Суммаризация** — провайдер (сервер / LiteLLM) и его параметры.
- **Глоссарий** — термины и аббревиатуры для ИИ.
- **Медиа** — настройки встроенного плеера и скачивания медиа.
- **Очередь** — авто-ретрай, интервал, максимум попыток.
- **Скрам** — шаблоны промптов, размеры окна, сортировка таблиц.
- **Форматы и сжатие** — аудио/видео битрейты, сжатие.
- **Хранилище** — путь к папке сессий и срок хранения.
- **Логи** — путь и уровень логирования.

Каждая вкладка содержит подсказки (ⓘ) для полей и кнопку «Помощь» с развёрнутой справкой.

В правом нижнем углу окна — **версия приложения**. Клик копирует номер в буфер.

### Кнопки внизу окна

- **Помощь** — справка по текущей вкладке.
- **Экспорт настроек…** — сохранить весь конфиг в JSON.
- **Импорт настроек…** — загрузить конфиг из JSON (с автоматической резервной копией).
- **Сбросить** — сбросить к значениям по умолчанию (с сохранением на диск).
- **Сохранить** — записать настройки на диск.
- **Закрыть** — закрыть окно без сохранения.

### Файл конфигурации

```
~/.config/screen-recorder/config.json
```

### Шифрование секретов

Мастер-ключ хранится в системном keyring (GNOME Keyring / KWallet). Если keyring недоступен — используется файл `~/.config/screen-recorder/.fernet_key` с правами `0600`.

Все API-ключи (Bitrix24 webhook, Sync API-key, TFS PAT, LiteLLM API-key) шифруются через Fernet.

Мастер-ключ можно экспортировать/импортировать (`get_raw_key` / `import_key` в `ConfigManager`) — для переноса между устройствами.

### Временные файлы

```
/tmp/screen-recorder/
├── app.log              # логи приложения
├── faulthandler.log     # C-стек при segfault
└── queue.json           # очередь задач
```

## Что происходит после обработки

1. Файлы **остаются** в `<temp_path>/sessions/<timestamp>/`.
2. Создаётся `session.json` с метаданными.
3. Вложения копируются в `<session>/attachments/`.
4. Выполняется **конвертация в аудио** (`video.mp3`) — если есть видео.
5. Если задан URL сервера транскрибации — выполняется **транскрибация**, результат сохраняется в `video.txt`.
6. Если включена суммаризация и настроен LiteLLM — создаётся `video_summary.md`.
7. Если запись помечена как **скрам-митинг** — собирается `deepseek_prompt.docx` (или `.md`/`.txt`).
8. Если включена TFS-выборка и есть шаблон WIQL — сохраняется `attachments/tfs_work_items.csv`.
9. Если включено извлечение поручений — создаётся `action_items.json` и `action_items_prompt.*`.
10. Если включена **автопубликация** и запись готова к синхронизации — запись уходит на сервер.

## Библиотека (поиск)

Полнотекстовый поиск по всем сохранённым записям. Без базы данных — сканирование файлов на лету.

- **Где искать**: стенограммы, протоколы, summary, вложения.
- **Fuzzy-поиск** для стенограмм (порог схожести, по умолчанию 82%).
- **Фильтры**: по проекту, категории, тегу (включая «— без тега —»), периоду дат.
- **Результаты**: показывают источник совпадения и фрагмент контекста. Можно открыть папку записи, найденный файл, сохранить копию.
- **Формирование промпта** из результатов: настраивается размер контекста до/после совпадения, максимум фрагментов, дедупликация, произвольная инструкция для ИИ.

## Синхронизация с сервером

### Настройка

1. В настройках → **Синхронизация**:
   - включите интеграцию;
   - укажите Base URL сервера;
   - введите API-ключ;
   - настройте таймауты, автопубликацию, автоподтягивание.
2. Проверьте подключение — кнопка **«Проверить подключение»**.

### Отметка «готово к синхронизации»

Пока флаг `sync_ready` не выставлен — запись считается черновиком:

- Автопубликация не запускается.
- Фоновый pull не перезаписывает локальные файлы.
- Локальные артефакты не удаляются, даже если их нет на сервере.

Поставьте галочку, когда запись полностью готова — в карточке метаданных, в окне «Записи» или в окне «Синхронизация».

### Публикация

- **Одиночная** — «Синхронизировать…» в окне «Записи» (`Ctrl+Shift+S`).
- **Массовая** — окно «Синхронизация» → вкладка «На сервер».
- **Автоматическая** — после обработки (если включено).

### Скачивание

Окно «Синхронизация» → вкладка «С сервера». Фильтры по проекту, категории, году, месяцу. Можно скачать выбранные записи или ввести Record ID вручную.

### Публичные ссылки

- В окне «Записи» — «Открыть в браузере» / «Скопировать ссылку».
- В окне «Синхронизация» → «С сервера» — открыть/скопировать для выбранной записи.
- В диалоге отправки в Bitrix24 → вкладка «Ссылка на сервер» — с выбором отображаемых блоков.

## Обработка ошибок

Все ошибки пишутся в лог:

```bash
tail -f /tmp/screen-recorder/app.log
# или в папку, указанную в настройках → Логи
```

При segfault — C-стек в `/tmp/screen-recorder/faulthandler.log`.

## Устранение неполадок

### 1. `externally-managed-environment` при `pip install`

Используйте venv:

```bash
sudo apt install -y python3-venv python3-full
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. `ModuleNotFoundError: No module named 'src.main'`

Запускать из корня проекта:

```bash
cd screen-recorder-app
python -m src.main
```

### 3. Пустые строки в `QComboBox`

В `resources/styles.qss` должно быть правило:

```css
QComboBox QAbstractItemView {
    background-color: palette(base);
    color: palette(text);
    border: 1px solid palette(mid);
    selection-background-color: palette(highlight);
    selection-color: palette(highlightedText);
    outline: none;
}
```

### 4. Меню в трее обрезано (GNOME)

```bash
sudo apt install -y gnome-shell-extension-appindicator
gnome-extensions enable ubuntu-appindicators@ubuntu.com
# logout/login
```

Резерв: правый клик по иконке трея.

### 5. Ошибки при транскрибации

- Проверьте URL сервера во вкладке **«Транскрибация»**.
- Если URL пустой — шаг пропускается.
- Логи: `tail -f /tmp/screen-recorder/app.log | grep transcribe`.

### 6. Ошибки при суммаризации через LiteLLM

- Проверьте URL и API key во вкладке **«Суммаризация»**.
- Кнопка **«Проверить подключение»** делает ping.
- Логи: `tail -f /tmp/screen-recorder/app.log | grep -i litellm`.

### 7. Ошибки при отправке в Bitrix24

**`USER_NOT_FOUND` при `im.message.add`**
- Чат не существует или вебхук не имеет к нему доступа.

**`CHAT_ID_EMPTY` при `im.disk.folder.get`**
- Не задан ID чата или формат неправильный. Используйте `chat2101` или `2101`.

**`DISK_OBJ_22000` («файл с таким именем уже есть»)**
- Уже обработано: имя файла получает временной отпечаток.

**`NO_ACCESS` / 403 от `disk.*`**
- У вебхука нет прав `disk` и/или `im.disk`.

**Файл загружается, но не привязывается к сообщению**
- Проверьте доступ к `im.disk.file.commit`.

**Сообщение ушло не всем получателям**
- Итоговый отчёт после массовой рассылки показывает статус каждого.

### 8. Ошибки TFS

**401 / 403**
- Проверьте PAT. Убедитесь, что у него есть права Work Items → Read.

**404**
- Проверьте Base URL и имя проекта.

**Пустой результат WIQL**
- Проверьте `@project` в запросе и выбранный проект.

### 9. Ошибки синхронизации

**Не публикуется запись**
- Проверьте флаг `sync_ready` — запись может быть черновиком.
- Проверьте `base_url` и `api_key`.

**413 (Payload Too Large)**
- Увеличьте `SCREC_MAX_ARTIFACT_MB` на сервере или уменьшите `max_artifact_mb` в настройках. Проверьте автосжатие.

**Конфликты при pull**
- Используйте флаг `sync_ready` для защиты активных записей.

### 10. Предупреждения Wayland про `transientParent`

```
qt.qpa.wayland: Failed to create popup. Ensure popup ... has a transientParent set.
```

Безобидное предупреждение, тултипы работают корректно.

### 11. «Библиотека» долго ищет

- Сузьте область поиска: выберите проект, категорию, тег, задайте период дат.
- Отключите поиск во вложениях, если они не нужны.

### 12. Кнопка «Сохранить» в настройках не срабатывает

Проверьте права на `~/.config/screen-recorder/`:

```bash
ls -la ~/.config/screen-recorder/
# владелец — вы, права 700 для папки, 600 для config.json
```

### 13. Приложение упало (segfault)

Загляните в `/tmp/screen-recorder/faulthandler.log` — там C-стек.

Пришлите его разработчику.
